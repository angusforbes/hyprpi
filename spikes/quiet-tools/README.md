# quiet transcript for one agent (J637 v3)

The real code is `pi-extension/quiet.ts`, loaded by hyprpi's own extension (`pi-extension/index.ts`), so it only exists in hyprpi agent windows and is off unless switched on for that agent. `quiet-tools.ts` here is the v2 spike (one dim line per call), kept for reference; `quiet-demo.ts` loads quiet.ts without a hyprpi daemon for the screenshots.

When on: ordinary tool calls draw nothing; a failed call is one amber line saying what failed (ctrl+o shows pi's full output); agent-to-agent traffic (talk, demand and its answers, talk_reply, ask_agent, give_work, spawn_agent, report_to_parent, wait_report's reports, and incoming talk/replies) is one dim line, `↪ to Sweep · …` / `↩ from Radio · …`; the agent's own replies and Angus's messages are unchanged. Only drawing changes; the model sees everything.

Switch: `PI_QUIET_TOOLS=1`, or the agent's hyprpi id in `~/.config/hyprpi/quiet-tools.json` (`{"agents": ["hp-…"]}`), read at start/reload; `PI_QUIET_TOOLS=0` forces it off.

What pi 1.0.2 allows:
- Tool rendering: yes, for built-ins too. `pi.registerToolRenderer((toolName, next) => renderers)` (docs/extensions.md, "Tool rendering", lines 188-190; CHANGELOG 1.0.x "Added `pi.registerToolRenderer()`") picks renderers for any tool name; a resolver that returns its own wins over the registered tool's, and `next()` gives pi's own (used here for ctrl+o and as a fallback). The older way, re-registering a built-in with `pi.registerTool({...createBashToolDefinition(cwd), renderCall, renderResult})` (examples/extensions/built-in-tool-renderer.ts), also works but replaces the tool.
- Thinking: no supported way per agent. Hiding thinking blocks is the `hideThinkingBlock` setting (docs/settings.md line 17; Ctrl+T toggles it and writes it to the user settings, i.e. for every agent). The documented extension API only changes the label shown in place of hidden thinking (`ctx.ui.setHiddenThinkingLabel`, docs/rpc-extension-ui.md line 18). An unsupported hack exists (QuietCheck637: walking the TUI's component tree from `ctx.ui.custom()` and calling `setHideThinkingBlock` on each message component), but it misses components created later and could break with any pi update, so it is not used. Per agent, thinking can only be hidden through settings that only that agent reads: its own `PI_CODING_AGENT_DIR`, or a project `.pi/settings.json` in a working directory only it uses.

Demo: `fixture.jsonl` (an incoming talk, 5 tool calls with a failing bash, a demand with its answer, a talk) opened with `PI_QUIET_TOOLS=0|1 pi --no-extensions -e quiet-demo.ts --session …` in a pi window on a private headless sway (scratch agent dir).

## J642: changes vs lookups (project agents)

Lookups draw nothing, even when they fail (a missing file, a grep with no match, a failing test run are harmless probes); the silent ones of a turn are counted in one dim tail line after it (`· ran 6 checks · ctrl+o: list`; a display-only session entry, never sent to the model). Changes are one dim line (`edited NOTES.md`, `wrote TODO.md`, `ran git commit -am x`); a change that failed is one amber line (ctrl+o: pi's full output). While a tool runs, pi's working line says what it is doing (`reading NOTES.md…`, `waiting on Sweep…`, `checking…`) through `ctx.ui.setWorkingMessage`; it goes back to normal when the turn ends.

Tools: read, grep, find, ls are lookups; edit and write are changes; agent traffic keeps its own lines; any other tool is a lookup when its name contains read/list/search/get/find/status/show/check (…), else a change.

Bash (`bashKind` in pi-extension/quiet.ts), a heuristic on the command text:
- change if it writes through a redirection (`>`/`>>` to anything but /dev/null or a fd), or inline python/node writes files (`open(…,'w')`, `write_text`, `writeFileSync`, `unlink`, `shutil.move` …);
- change if any segment (split at `;`, `&&`, `||`, `|`, newlines, `$(`) starts with a known acting command (rm, mv, cp, mkdir, touch, ln, chmod, tee, kill, pkill, sudo, systemd-run, setsid, ssh, rsync, tar, grim, notify-send …), or a command that acts with some subcommands only (`sed -i`, `git commit/push/checkout/…` (anything but status/log/diff/show/…), `systemctl start/stop/restart/enable…`, `hyprctl dispatch/keyword/reload`, `pacman -S/-R`, `curl -X POST/-d/-o`, `docker run/rm/…`, `npm install`, `make install`, `hyprpi` anything but list/status/search, `tmux` anything but ls/capture/display, `pactl load-/unload-/set-`), or a local script (`./x.sh`) unless its name says test/check/lint/verify/status/list/show;
- otherwise a lookup (ls, cat, grep, find, git status, systemctl status, journalctl, tests, builds without install …).
Limits: it reads the text only (checked against 71 realistic commands: 69 as intended). A script run by path through an interpreter (`python3 manage.py migrate`, `node scripts/update.mjs`), or a binary it doesn't know, that writes files counts as a lookup (shown in the tail, not as a grey line); a command that only looks like it writes (`echo x > /tmp/scratch`) counts as a change; `python3 script.py` and `node x.mjs` are lookups unless their inline code writes; a lookup that times out or fails stays silent (it's in the tail as "(failed)"). Wrong guesses only change how the call is drawn, never what runs or what the model sees.
